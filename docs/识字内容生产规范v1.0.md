# 幼儿识字 APP · 内容生产规范（v1.0）

> 本规范是所有汉字「五步学习法（玩 / 认 / 说 / 练 / 写）」内容产出的**唯一标准**。
> 无论人工撰写还是代码自动生成，都必须遵守。后续每生产一个新字，均按本规范执行。

## 一、角色与适用范围
- 受众：4–6 岁学龄前儿童。
- 每个汉字产出一套内容，覆盖 5 个环节：**玩、认、说、练、写**，顺序固定、不可增减。

## 二、铁律（违反即不合格）
1. **语言儿童口语化，禁止书面词典语**
   - ❌ 赠给、购置、进食、吞咽、展露喜悦之情……
   - ✅ 把东西拿给别人、花钱把东西拿回家、嘴巴弯弯哈哈笑……
   - 判断标准：4–6 岁孩子能听懂吗？听不懂就重写。
2. **练习题干扰项必须有辨析价值**
   - ✅ 形近字（同部首/部件）、同音字（声调不敏感也算）。
   - ❌ 完全无关字（读音字形都没关系）。
   - 干扰项必须来自**已学字库**，不能出现未学过的字。
3. **所有界面指令文字 ≤ 5 个字**
   - ❌「请点击下面的正确答案」→ ✅「选一选」
   - ❌「请大声朗读下面的句子」→ ✅「读一读」
   - ❌「请观察动画并思考这是什么字」→ ✅「看一看」
4. **反馈语必须鼓励，禁止批评**
   - 答对：✅「真棒！」「答对啦！」+ 加星星。
   - 答错：✅「再试试~」「差一点点，再看看」——**永远不打叉、不说"错了"**。
   - ❌ 不使用：「错误」「不对」「答错了」。
5. **句子只能用已学过的字**
   - 生成短句时，句中每个字都必须是已学字；不确定就用更简单的字替换，或只给单字和词语、不给句子。

## 三、五个环节输出模板（每个字严格按此格式）

### 环节 1：玩（故事导入）
- 目的：先用小画面让孩子"看见"字的意思，**字最后一步才亮出**。
- 字段：画面描述、动画流程（2–3 步，字最后）、旁白配音（儿童口吻、引号）、互动点。
- 禁止：一开始就亮字、只有字无画面、"猜一猜这是什么字"式无信息引导。

### 环节 2：认（识字理解）
- 字段：拼音（带声调）、大字、口语释义（≤15 字、口语）、字形提示（一句话拆解）、配图、词语列表（≥3 个，每个带场景配图）。
- 禁止：书面释义、无配图、词语干巴巴无场景。

### 环节 3：说（跟读朗读）
- 三层：**单字 → 词语 → 短句**，逐层开口读。
- 短句要求：所有字均为已学字、≤10 字、带配图。
- 禁止：只给单字不给词/句、句子含未学字、句子超 10 字。

### 环节 4：练（巩固习题）
- **3 道题**，题型：①听音选字 ②看图选字/选词 ③句子填空。
- 硬性：每题 3–4 选项；干扰项必为形近/同音且来自已学字库；提问 ≤8 字；句子填空句子 ≤12 字；选项无未学字。

### 环节 5：写（笔顺描红）
- 字段：总笔画数、笔顺步骤（顿号分隔）、易错提示（一句话，无则写"无"）、描红引导（4 阶段：看动画→分步描→灰字影描→空格写）。
- 禁止：笔顺错误、不提示易错、不写总笔画数。

## 四、数据落库约定（代码生成时对照）
每个字在 `characters` 表至少应有：`hanzi, pinyin, meaning, words, stroke_count, emoji`。
规范额外要求、但表中未直接存储的字段，由 `client/src/utils/lessonContent.js` 生成或走覆盖表：
- `oral`（口语释义）→ 优先 `ORAL` 覆盖表，否则退回 `meaning` 并告警。
- `shapeHint`（字形提示）→ 优先 `SHAPE` 覆盖表，否则模板兜底。
- `writeHint`（易错提示）→ 优先 `WRITE_HINT` 覆盖表，否则"无"。
- `play / speak / practice` → 由生成器按上述模板与铁律推导（emoji 作配图占位，后续可换实拍/插画）。

## 五、质量自检清单（产出后逐条核对）
- [ ] 释义口语？有无"赠给/购置"等书面词
- [ ] 干扰项形近/同音？有无无关字
- [ ] 界面指令 ≤5 字
- [ ] 句子无未学字
- [ ] 反馈无"错误/不对"
- [ ] 玩：字最后才亮出
- [ ] 笔顺正确 + 易错提示
- [ ] 词语/句子有配图描述
- [ ] 新增字已完成 TTS 音频合成（见第六节；否则该字固定朗读仍走 Web Speech 兜底，听不到晓晓）

## 六、新增汉字后必须重新生成朗读音频（TTS）⚠️

> 固定朗读内容（听读音 / 玩·旁白 / 认·听讲解 / 词组 / 说·短句）是**离线预合成**的 mp3（微软晓晓/晓伊，由 python edge-tts 烤盘到 `server/tts-audio/`）。
> 绘本、跟读等**动态文本**不预合成，始终走浏览器 Web Speech 兜底。
>
> **每生产 / 新增一个字，都必须执行下面两步补合成，否则这个新字的固定朗读会回退成浏览器默认声音（听不到晓晓）。**

### 步骤（需后端 3001 在运行）
1. **导出新增短语**：从后端字表重新推导全部固定文案，整份覆盖 `phrases.json`（已存在的短语会保留）：
   ```bash
   node server/scripts/gen_phrases.mjs
   ```
2. **增量补合成**：断点续跑——已存在且非空的 mp3 自动跳过，只合成 `phrases.json` 里多出来的新 key：
   ```bash
   python server/scripts/gen_tts.py
   ```
   - 依赖：`pip install edge-tts`（装一次即可）。
   - 加 N 个新字 ≈ 多合成 N×5~10 条，几秒到十几秒，**不重做已有的、不用等全量**。
   - 文案完全相同的（如不同字共用的词组）会被自动去重，已存在则不补。

### 注意事项
- 改了某字的旁白 / 释义文字 → 该条 key 变化，旧 mp3 变孤儿文件（留着无害），新的一条会被补上。
- `server/tts-audio/` 是后端静态资源。**部署 / 迁移后端时必须整目录一起带走**，否则新环境 404 → 回退 Web Speech。
- 首次全量合成 6558 条约 25–30 分钟（12 路并发）；中途断开重跑即可，已生成的会被跳过。
